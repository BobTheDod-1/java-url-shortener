# Консольный сервис сокращения ссылок

Консольное приложение на Java 17 или новее. Внешние библиотеки не используются.

## Запуск

Из корня проекта на macOS/Linux:

```sh
sh build.sh
java -jar url-shortener.jar
```

Необязательный аргумент — путь к конфигурации:
`java -jar url-shortener.jar config.properties`.

Для Windows без shell: `javac --release 17 -encoding UTF-8 -d build/classes src/shortener/*.java`,
затем `java -cp build/classes shortener.Main` из корня проекта.

## Команды

| Команда | Действие |
|---|---|
| `create https://example.org/article 3` | Создать ссылку с тремя переходами |
| `create https://example.org/article` | Создать с лимитом из конфигурации |
| `list` | Показать свои ссылки, адреса, счётчики и срок |
| `open https://short.local/КОД` | Открыть исходную страницу в системном браузере |
| `https://short.local/КОД` | То же без open |
| `limit https://short.local/КОД 5` | Владелец изменяет лимит |
| `target https://short.local/КОД https://example.net/` | Владелец изменяет исходный URL |
| `delete https://short.local/КОД` | Владелец удаляет ссылку |
| `user UUID` | Выбрать свой UUID; UUID надо сохранить из вывода create |
| `new` | Начать сессию другого пользователя; UUID создастся при create |
| `notifications` | Получить накопленные уведомления |
| `help`, `exit` | Помощь, выход |

`КОД` замените реальным кодом из результата create. При первом успешном create сервис генерирует UUID
и печатает его вместе с короткой ссылкой. Скопируйте UUID, чтобы вернуться к своим ссылкам через `user`.
Один пользователь может создавать несколько ссылок. Разные пользователи получают разные коды даже для одного URL.
URL со встроенными логином и паролем, пробелами и схемами кроме http/https отклоняются.

Для управления ссылками используется UUID владельца. Команда `user` выбирает пользователя по UUID.

## Настройки

Все ключевые параметры читаются из `config.properties`:

| Параметр | По умолчанию | Значение |
|---|---|---|
| short.prefix | https://short.local/ | Пространство коротких ссылок |
| link.ttl | PT24H | Срок жизни в ISO-8601 Duration |
| clicks.default | 10 | Лимит при create без аргумента |
| clicks.max | 1000000 | Верхняя граница лимита |
| cleanup.millis | 1000 | Интервал фонового удаления, мс |

TTL задаёт администратор в конфигурации; пользователь через консоль менять срок не может.
При `now >= expiresAt` переход уже запрещён. Планировщик удаляет просроченные записи независимо от команд
примерно на ближайшем тике (обычно до cleanup.millis; возможны задержки планирования JVM/ОС).
Дополнительно перед чтением/изменением проверяется срок, поэтому задержка планировщика не продлевает доступ.

Исчерпание лимита блокирует ссылку. Владелец может увеличить лимит и снова разрешить переходы;
уменьшить лимит ниже уже выполненных переходов нельзя. Истёкшая/удалённая ссылка не восстанавливается.
При достижении лимита и автоудалении формируются уведомления владельцу, которые консоль показывает
перед следующим приглашением ввода. Пока консоль ждёт ввода, уведомление будет показано после следующей команды.

Переход вызывает `Desktop.getDesktop().browse(originalUri)`. Вызов браузера, завершившийся ошибкой,
не расходует лимит. Учёт успешного вызова означает передачу URL системному браузеру, а не подтверждение загрузки сайта.

## Архитектура и модули

- `Link`: неизменяемая модель ссылки (UUID владельца, URI, лимит, переходы, expiresAt).
- `LinkService`: core, генерация кодов, права, изменения, подсчёт переходов, TTL и очередь уведомлений.
  Clock, генератор кодов и BrowserOpener передаются как зависимости. Операции синхронизированы:
  одновременные вызовы не превышают лимит. Код — 10 символов UUID; при коллизии выполняется повторная попытка.
  Множество использованных кодов исключает повторное назначение даже после удаления записи в пределах процесса.
- `BrowserOpener` / `DesktopBrowser`: инфраструктурный контракт и открытие браузера.
- `Config`: загрузка/проверка Properties.
- `Console`: UI; принимает потоки ввода/вывода, не зависит от реального браузера.
- `Main`: сборка зависимостей и корректное закрытие планировщика.

Хранилище находится в памяти: ссылки, UUID-связи и уведомления существуют до завершения процесса.
`short.local` — консольное пространство имён, не зарегистрированный интернет-сервис.
Короткие ссылки открываются командой этого приложения; введённый в адресную строку браузера short.local не обслуживается.

## Тестирование

```sh
sh test.sh
```

30 unit/интеграционных проверок: уникальность, несколько пользователей, ACL, точный лимит,
изменения владельцем, ошибки URL/конфигурации, коллизии, TTL на границе, независимый фоновый cleanup,
очередь уведомлений, CLI и 50 конкурентных попыток перехода при лимите 5.
Часы в тестах подменены, поэтому не нужно ждать сутки. Для ручной проверки TTL замените link.ttl на PT5S
в отдельной копии конфигурации и перезапустите приложение.

Сборка выполняется с `javac -Xlint:all -Werror`.
GitHub Actions в `.github/workflows/java.yml` запускает сборку, тесты и проверку whitespace.
Настройки форматирования находятся в `.editorconfig`.
